Learn, Simulate & Mitigate Cross-Site Scripting (XSS)

Cross-Site Scripting (XSS) is a critical class of web security vulnerability where an application includes untrusted data in a web page without proper validation or escaping. This allows attackers to execute malicious scripts in the context of a victim's browser session. Explore each vulnerability tab to test payloads, view vulnerable code, and examine secure solutions.

Core XSS Vulnerabilities Covered

📡

Reflected XSS

Input from an HTTP request (like query parameters) is immediately returned by the server and rendered onto the page without sanitization. Typically executed via crafted links sent to victims.

💾

Stored XSS

The injected script is permanently saved on the server (like in a database or file). It is later served to other users visiting the affected pages, leading to wide-scale execution.

🌐

DOM-based XSS

The vulnerability exists entirely in client-side script logic. Unsafe inputs (like URL hashes or query strings) are written directly into execution sinks (like innerHTML) by frontend code.

Universal XSS Defense in Depth

Modern applications prevent XSS by combining context-aware output encoding, input sanitization, and server-side sandboxing rules like Content Security Policy (CSP).

1. Context-Aware Output Encoding

Always encode user input before rendering it. The encoding method depends on where the data is placed inside the HTML document:

  • ✓
    HTML Body Context: Convert characters like <, >, and & into HTML entities.
  • ✓
    HTML Attribute Context: Escape quotes and spaces to prevent attackers from breaking out of attributes.
  • ✓
    JavaScript Context: Parse dynamic variables inside JSON block structures rather than injecting inline text.
Standard HTML Escaper Function
function escapeHTML(str) {
  return str
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#x27;')
    .replace(/\//g, '&#x2F;');
}

2. Content Security Policy (CSP)

CSP is an HTTP response header that dictates which resources (scripts, stylesheets, images) the browser is permitted to load, serving as a powerful mitigation filter against script injections.

Default Policy (Vulnerable)
Allows inline scripts and third-party remote scripts to execute.
No CSP
Strict Policy (Protected)
Blocks all inline script injection blocks. Requires cryptographically signed nonces or local hashes.
